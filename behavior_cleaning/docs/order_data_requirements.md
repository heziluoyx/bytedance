# 订单数据需要提供什么

现有字段只有时间、用户、商品、类目和行为类型。行为类型4表示购买行为记录，不能由此生成真实订单号、交易金额或退款金额，也不能把重复购买事件直接当作多笔订单。

## 最小可用订单表：计算真实 RFM、客单价、用户复购

建议提供 `orders.csv`，一行一笔业务订单。若平台有父子订单，必须明确哪个订单粒度用于计数，并保持全表一致。

| 字段 | 是否必需 | 说明 |
|---|---|---|
| `order_id` | 必需 | 唯一订单号，按字符串提供；明确父单/子单粒度 |
| `user_id` | 必需 | 与当前行为表使用同一套匿名ID，保留前导零 |
| `paid_at` | 必需 | 支付成功时间，建议精确到秒，明确时区（建议Asia/Shanghai） |
| `paid_amount_fen` | 必需 | 该订单实际支付金额，整数“分”；不能用商品标价乘数量代替 |
| `order_status` | 必需 | 已支付、已取消、已关闭等；同时提供状态值说明 |
| `currency` | 必需或全表声明 | 如统一为CNY可在说明中固定，混币种不能直接相加 |
| `refund_amount_fen` | 净消费口径必需 | 已成功退款金额；无退款明确填0，未知不能填0；说明统计截至时间 |
| `created_at` | 建议 | 下单时间，用于分析下单到支付时长及未支付流失 |
| `completed_at` | 建议 | 交易完成时间，若分析口径要求完成交易则需要 |

`paid_amount_fen`必须说明是否包含运费、是否包含平台或商家补贴、是否包含优惠券抵扣。用户现金支付、平台补贴与商家结算属于不同金额口径，不能混用。

以上数据可支持：R=截至分析时点距离最近一次有效支付的时间；F=观察窗内有效订单去重数；M=有效实付总额或净消费总额；客单价=同口径金额/有效订单数；用户复购率=至少两笔有效订单用户数/至少一笔有效订单用户数。

如采用净消费口径，可约定成功退款从金额中扣除；全额退款订单是否计入F/R须提前固定，不能在不同报表中变换口径。不要把取消未支付订单当购买，也不要把多商品订单按商品行数累计为多笔用户订单。

## 商品/类目复购、购买数量和商品销售额：增加订单明细表

建议提供 `order_items.csv`，一行一个订单商品明细。仅有订单总表无法可靠计算商品或类目复购。

| 字段 | 要求 |
|---|---|
| `order_item_id` | 唯一明细ID；或明确`order_id + line_no`组合主键 |
| `order_id` | 关联订单总表 |
| `item_id` | 必须与行为表商品ID一致，避免用无法映射的SKU替代 |
| `sku_id` | 如有规格，另列SKU；明确复购按商品SPU还是SKU统计 |
| `category_id` | 成交时类目，或提供有效商品类目映射 |
| `quantity` | 实际购买数量，正整数 |
| `allocated_paid_amount_fen` | 该明细分摊后的实际支付金额，需说明运费/优惠分摊 |
| `allocated_refund_amount_fen` | 该明细成功退款金额；或通过退款明细推导 |

一笔订单的多条明细金额应与对应口径的订单实付总额勾稽。如果运费单独计列，则商品分摊金额加运费与订单实付勾稽；不要把订单总额复制到每一条商品明细后相加。

同一订单买2件同款商品不等于复购；同一用户在至少两笔不同有效订单购买同一商品，才可按订单口径认定该商品复购。统计类目复购时还应对订单和类目去重。

## 做未来7天预测或历史回测：退款和状态必须带时间

订单当前最终状态不足以还原历史。应再提供退款流水或订单状态变更日志，至少有：

- `refund_id`、`order_id`，商品退款还需`order_item_id`；
- `refund_amount_fen`、`refund_status`、`refund_succeeded_at`；
- 状态变更记录中的`status`、`effective_at`，或按日保存的订单快照；
- 数据导出时点、完整覆盖起止日期、是否存在抽样或漏数的说明。

例如12月5日构建特征时，只能扣除12月5日前已成功的退款，不能提前使用12月10日才发生的退款。未支付订单的`paid_at`应为空，不得填下单时间。对取消、全退、部分退款以及退款后仍存在有效支付的订单，须按同一约定处理。

为了计算较稳定的RFM和复购，建议提供至少3个月、最好6至12个月的历史；当前31天只能得到观察窗内复购，不能声称用户终身首次购买或终身复购。未来7天标签还需额外完整覆盖对应7天，并注明退款观察口径。

不需要姓名、手机号、地址、银行卡等身份或支付凭证。匿名用户ID能够与当前行为数据稳定关联即可。
