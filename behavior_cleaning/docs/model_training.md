# 用户商品未来七天购买模型

最新补充：本说明以下为原12月12日单截点基线。针对双十二代表性风险，已在11月25日较早截点重训三种传统模型，并冻结评估后期窗口；两期统一7天历史。新旧历史长度、测试规模和目标时期不同，不直接把分差归因为促销。详见 [双十二窗口复核](promotion_review.md)；输出为 `outputs/promotion_review_20261104`。

本阶段与此前用户级购买预评估分开运行：本阶段每行是一个用户—商品对，预测它在指定时点后的完整7天内是否出现购买行为。购买标记不是已核验支付订单。

## 运行方式

建议使用Python 3.10或以上独立环境。在仓库根目录安装：

```powershell
python -m pip install -r behavior_cleaning/requirements-modeling.txt
```

本机使用项目 `.runtime` 与 `.model_runtime` 内的补充依赖，启动脚本会自动识别这些目录，不需要修改系统Python。新环境可直接安装依赖文件；若使用较旧Anaconda且预装Dask与pandas不兼容，应在独立环境安装，或更新匹配的Dask与distributed，避免修改平台包源码。

完整执行：

```powershell
python behavior_cleaning/scripts/train_purchase_models.py --run-dir behavior_cleaning/outputs/my_model_run
```

为使数据聚合阶段和训练阶段分别释放内存，本机采用两步执行：

```powershell
python behavior_cleaning/scripts/train_purchase_models.py --stage data --run-dir behavior_cleaning/outputs/my_model_run
python behavior_cleaning/scripts/train_purchase_models.py --stage train --run-dir behavior_cleaning/outputs/my_model_run --trials 8 --deep-trials 2 --epochs 6 --lstm-epochs 10
```

`--database`可指定保留正常重复后的SQLite；`--cutoff`默认2025-12-12 00:00:00；`--max-pairs`默认120000；`--trials`是每种传统模型的调优次数，`--deep-trials`是每种深度架构的试验次数，`--epochs`为每次深度训练的最大轮数，`--lstm-epochs`可单独设置LSTM上限。本轮LSTM最多10轮，其余三种深度架构最多6轮。一个运行目录只允许同时运行一个训练进程。

已完成的运行会有 `SUCCESS` 标记，不再重复调参或测试。失败后可用同一 `--run-dir --stage train` 继续，已完成的模型族从检查点恢复，未完成的试验重新执行。不要修改同一目录中的样本、已保存超参或观察截止时间。

## 样本定义

- 标签1：同一用户和商品在 `[预测时点, 预测时点+7天)` 有购买记录；否则为0。
- 候选池只由预测时点前7天发生过交互的用户—商品对形成。所有特征使用严格早于预测时点的历史，未来记录只决定标签。
- 对候选池做不依赖未来标签的均匀蓄水池采样，控制CPU与内存占用。不是将全商城用户与商品笛卡尔积全部作为负例。
- 抽样后按标签分层7:2:1划分训练、验证、测试，随机种子42；同一用户或商品可以跨集合出现，同一个用户—商品对不会重复。
- 三个集合共享固定时点，不能声称这是时间外测试；正式上线还需多个时点的滚动回测和冷启动验证。

本地候选池1,145,910对，未来购买7,781对；均匀采样120,000对。训练84,000对、540正例；验证24,000对、155正例；测试12,000对、77正例。候选规则覆盖整个标签窗口内已观测购买组合的约23.92%，效果只适用于近期交互候选池。

## 特征与训练隔离

数值特征包括用户、商品、用户商品交互量、购买占比、活跃天数、最近行为间隔及类目目标编码。历史统计不使用未来记录；缺失填补中位数、标准化仅训练拟合；类目训练目标编码使用5折折外统计，验证测试仅套用训练映射。原始用户ID、商品ID不直接当作连续数值输入传统模型。

序列采用最近7天内最后16个活跃小时，每小时最多4件商品，按历史行为权重选择后池化。记录小时内四种行为比例、时间间隔以及候选商品是否出现。每个小时是一个序列位置，不人为排序同小时内操作。训练样本与训练用户历史拟合最多20,000件商品词表，其余为未知标记；类目词表同样训练拟合。

目前商品嵌入未知率较高，是深度模型的重要限制。数值历史、类目和原始候选匹配标记仍可使用，不能将全部未知商品误认为同一个真实商品。已有清洗规则曾参考全期阈值，正式端到端时间验证还需仅按历史拟合清洗参数。

## 模型及不平衡方案

逻辑回归、XGBoost和LightGBM分别进行不处理、SMOTE、随机欠采样、类别权重四组基础训练。只处理训练集，保持验证测试原始正例比例；各模型按验证AUC选择方案后，分别使用Optuna优化关键参数。

SMOTE只作用于处理后的连续数值特征和编码，不合成用户、商品ID或序列。原始计数在合成空间可能变为小数，这只是比较算法的训练输入，不当成真实行为。欠采样可能丢失多数类信息；类别权重可能使输出概率偏离自然购买率。报告必须结合实际结果比较，不能预设任一处理必然提升模型。

深度部分包含LSTM、GRU、DIN及DIN_MHA，使用真实小时桶序列及类别权重。DIN采用候选与历史的局部激活机制，属于小时桶和购买标签适配版本；DIN_MHA增加多头自注意力。搜索嵌入维度8或16、隐藏层32或64、Dropout 0.1至0.4和学习率，多头扩展搜索2或4个头。

采用Adam、梯度裁剪、学习率衰减和验证AUC早停；保留最佳epoch状态。CPU线程设为2，不需要CUDA。默认预算用于初步比较，不等于完成大规模参数搜索。

## 指标和输出

所有模型及超参选择完成后，才统一输出测试结果。主指标是AUC，另提供AP、准确率、精确率、召回率、F1和Brier分数。分类阈值在验证集上最大化F1后固定用于测试；另保存0.5阈值准确率。
