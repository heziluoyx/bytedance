# 多路径购买行为复核

在仓库根目录运行，脚本仅依赖 Python 3.10+ 标准库：

```powershell
python behavior_cleaning/scripts/analyze_purchase_paths.py
```

可通过 `--database` 指定新版 SQLite，通过 `--output` 指定尚不存在的输出目录。默认读取 `outputs/sql_analysis_v2/user_behavior.sqlite`，使用只读连接，输出汇总 JSON、CSV 和 SUCCESS；不改源数据库，不覆盖既有结果。SQL 位于 `sql/04_purchase_paths.sql`。

## 统计定义

- 单位是不同的用户—商品组合，不是事件数、订单数或支付用户数。
- 分别以首次观测浏览、加购、收藏作为起点，统计同一组合后续购买。三种路径可以重叠，不能相加。
- 全期比例从起点观察至数据结束，每个起点的观察长度不同。
- 完整7天比例仅纳入起点后有完整168小时观察的组合，购买时间须位于 `(起点, 起点+168小时]`。分母、分子均按该起点人群计算。
- 同小时内不能判断顺序，后续购买要求小时记录更晚；不能伪造秒级先后。
- “无此前或同小时加购收藏的浏览后购买”仅描述窗口内已观测路径；不等于已证实全生命周期的直接支付。
- 首次购买前分组使用窗口内首次观测购买；重复购买可以计入相应起点的后续购买。

## 本地全量复核结果

数据期为2025年11月18日至12月18日，共12,204,330条清洗后记录。完整观察起点截至12月11日23时。

| 起点 | 全期后续购买 | 完整7天后续购买 |
| --- | --- | --- |
| 浏览 | 54,305 / 4,677,501，1.16% | 38,094 / 3,567,270，1.07% |
| 加购 | 24,173 / 282,429，8.56% | 17,667 / 215,401，8.20% |
| 收藏 | 8,302 / 228,240，3.64% | 5,804 / 176,095，3.30% |

102,996个有购买的组合中，10,230个在首次购买前有较早浏览，却没有此前或同小时加购收藏；36,230个没有更早意向记录，但在首次购买同小时存在加购或收藏，属于顺序不明。不能把“没有更早小时意向”全部当作直接购买。

加购起点的后续购买比例较高，支持优先进行意向承接试验；不能解释为加购的因果提升或发券收益。当前只有行为标记，不能确认支付失败、运费、缺货等具体原因，也不能计算订单成交额或净利润。

对应最新版报告位于 `../reports/核心数据洞察总结.docx`。训练过的用户级购买模型与本次用户—商品路径描述是两种分析，不可混用模型指标。
