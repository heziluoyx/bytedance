# 项目全流程复盘

## 数据处理

最初统一去重会把真实的重复浏览与比较行为一起删除。修订后先观察同一操作频次及不同小时的间隔，在全体小时量阈值206之上，再结合个人稳健基线或极端重复证据判断异常。最终只压缩417个异常小时中的冗余，保留各操作至少一条，隔离52,576行，保留12,204,330行。规则仍是统计识别，不能宣称证实机器人；阈值使用全时段，是建模前视局限。

SQLite旧唯一四元组约束与正常重复保留冲突，因此新版取消该唯一约束，使用只读分析连接、批量导入、索引及行数和完整性核对。Parquet和用户、商品、时间聚合减少重复计算；没有原始日志的完整事件ID，无法精确识别数据重复上报。

## 特征与分析

描述性全期聚合不能直接输入未来预测。早期用户级特征使用历史快照、训练期SVD和训练内筛选，61项输入筛出30项；但隐式商品只覆盖热门1,000件商品，不能把低贡献当作全目录语义无用。后续用户商品对采用26项特征，未重新执行全部统计筛选，字段名去重与统计去冗余分别说明。

只有小时级时间，无法识别同小时行为顺序。严格四步漏斗不是购买必经路径，低路径通过率不能直接称为真实流失率。重新检查浏览、加购、收藏起点的完整7天后购买，分别为1.07%、8.20%、3.30%，各人群有重叠。中国大陆2025日历接入完成，但观察期没有法定节假日，只能比较工作日与普通周末。

## 模型与评估

早期同一截点随机7:2:1得到较高AUC，随后发现它不能回答跨时间泛化。固定较早窗口与双十二压力样本的传统模型复核后，最新版本改为四个不重叠7天标签窗口，统一3天历史，独立参数验证与用户互斥的融合、校准组。数据只有31天，采用3天历史是覆盖完整标签的折衷，不能说长历史已经验证。

类别权重对部分模型排序有用，却显著改变原始概率；自然分布校准改善尺度，但双十二购买率跃升后仍低估。应同时报告AUC/AP与Brier、校准分桶、预算命中。复杂序列模型没有稳定胜过树模型；最终词表外商品约95.97%，应先补属性和覆盖，再增加网络复杂度。

融合需要与同预算单模型比较。原Stacking并非所有预算都更好；补充概率权重搜索得到XGBoost 0.7和DIN 0.3，但额外模型开销较大。去掉某个模型重新拟合的消融，比融合系数或注意力权重更适合判断是否值得保留。补充结果已接触最终测试，只能作为后续验证候选。

## 工程化遇到的问题

推理不能继续调用要求两类未来标签的训练快照，因此增加无标签历史分支，完全跳过未来事件查询。训练期Target Encoding是float32，推理若先拼接成float64，微小差异会让树模型在阈值附近换分支；现统一精度并增加真实八模型回放。DuckDB连接返回的行序不是预测契约，因此推理输出固定按用户和商品排序。

pytest此前卡在收集阶段，实际堆栈指向向本机Anaconda依赖目录写入断言缓存，采用`python -B -m pytest --assert=plain`后恢复。该改动不关闭测试断言。发布包提供稳定API、CLI、锁定依赖、示例、模型包校验和独立回放脚本；没有把离线批量接口包装成已验收的在线服务。

## 局限与优化优先级

近期优先补订单支付、退款、优惠成本、库存和曝光来源，取得新的独立日常与活动窗口，校准真实支付目标。按训练期拟合清洗阈值，延长历史，增加候选覆盖并为零历史用户设计独立召回。以有效支付与净贡献验证推荐策略，保留用户级随机对照。

中期引入商品标题、属性、图片或评论的内容表示，降低UNK依赖；补实时浏览、加购、库存和到手价，监控事件时间、到达延迟与特征一致性。实时特征必须有可审计截止时间，不能把晚到订单回填进当时预测。

更长序列和更多正例到位后，再比较Transformer或其他兴趣模型，与现有树模型在一致候选、时间窗和资源预算下验证；并联合购买、退款与履约质量目标。新架构不能替代数据质量、概率校准或真实A/B。
